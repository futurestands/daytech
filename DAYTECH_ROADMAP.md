# DayTech roadmap

Milestone 2 starts after Milestone 1 passes verification and is submitted to GitHub for review.

| Milestone | Dependencies | Implementation tasks | Acceptance criteria and verification |
| --- | --- | --- | --- |
| 1. Security and authentication | Bun lockfile, Node, Java, isolated Firestore emulator, GitHub write access | Protect administrator provisioning, enforce Firebase staff sessions, isolate customer lookup, and rotate quotation signing configuration | Verify all seven roles, client-only registration, disabled accounts, ownership isolation and signed-link expiry. Pass TypeScript, build, Vitest and Firestore emulator checks. Submit a PR with evidence. |
| 2. Frontend and backend integration | Milestone 1 review submission, isolated Firebase environment | Connect forms, quotation generation and acceptance, persistence and Vercel routing. Centralise server financial validation. | Enquiry, demo and contact submissions each create one stored record. A quotation fixture produces the expected UGX totals. The assigned client can accept a sent quotation. Run integration and browser tests. |
| 3. Dynamic CMS and business operations | Stable persistence, agreed role matrix and schemas | Complete CMS, customers, products, pricing, enquiries, projects, tickets, documents, audit, reporting and settings. Split large components as needed. | Verify each module's supported create, edit, read and lifecycle operations. Confirm draft content stays private and privileged mutations create audit records. Run role-based acceptance tests. |
| 4. DayTech Academy and tutorials | Milestone 3 administration, Firebase learner accounts, approved course materials | Add catalogue, free tutorials, learning paths, YouTube embeds, knowledge base, resources, bookmarks, progress, quizzes, certificates and publication tools. | Demonstrate free access without login, private progress, draft isolation and certificate issuance only after completion. Link tutorials from product pages and the portal. Run learner and instructor browser tests. |
| 5. AI Voice and Google Maps hardening | Existing integrations, deployment capability verification, agreed usage ceilings | Add microphone consent, session limits, rate limits, fallback, feature flags and key restrictions. Verify voice transport and tutorials assistance. | Confirm microphone starts after consent, limits terminate sessions, disabled flags avoid calls, restricted Maps keys function on approved hosts, and the site works with both integrations disabled. |
| 6. Automated testing and CI/CD | Stable acceptance paths and isolated test configuration | Add GitHub Actions for frozen install, lint, build, Vitest, emulator and Playwright. Publish test output and enforce required checks. | A clean run verifies all jobs. Controlled failed assertions block the required check. Test jobs use isolated projects and fixture data. Verify branch protection with a test PR. |
| 7. Production deployment and commercial readiness | Review approvals, confirmed Firebase and Vercel configuration, budget | Validate health, SEO, mobile, accessibility, performance, backups, recovery, privacy and rollback. Document operating costs. | Run predeployment smoke tests and a restore and rollback drill. Verify sitemap, robots, portal sign-in, production health and the approved spend ceiling. Record deployment approval and release evidence. |
